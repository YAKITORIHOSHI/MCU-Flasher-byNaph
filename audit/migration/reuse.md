## Disposition rules

| Disposition | Meaning | Retirement condition |
| --- | --- | --- |
| Reuse unchanged | Preserve existing compatible bytes/configuration/template inputs. | Upgrade separately with provenance and regression evidence. |
| Host adapter | Keep content/model/rendering behavior; replace Qt/Tk/Python transport or widget ownership. | Every caller, reply/error, revision and native lifecycle passes its contract. |
| Retain tool runtime | Keep Python hooks integrated with PlatformIO/builders and approved firmware tools. | Retain while the external tool needs them; this does not retain a Python GUI/backend. |
| Behavior-preserving port | Move application state/services to Rust/shared UI using original success/failure contracts. | Differential, native integration, coexistence and rollback gates pass before legacy removal. |
