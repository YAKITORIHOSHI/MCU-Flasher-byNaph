# Lite workbench

Read this directory's AGENTS.md, README.md and VERIFICATION.md. Work only inside
LITE-MODE; main application instructions about updating parent documentation and
skills do not authorize unrelated original-file edits. The user explicitly approved
shared Bootstrap/release source inventories and their guidance; keep the main
GUI, firmware backend and protected state unchanged.

Keep Rust as the GUI owner. Reuse the headless Python backend through its private
snapshot and bounded literal-command JSON protocol. Do not add arbitrary RPC
dispatch, shared settings or writes into original projects/runtimes. Native
Windows short paths must stay in Lite's own state-hashed namespace; never invoke
legacy alias cleanup or rewrite a user's global PlatformIO config.

Use neobrutalist paper/charcoal bases with yellow/coral accents, Montserrat headings, hard black
outlines/shadows and dedicated SVG actions. Preserve selectable output, virtual
log rows, independent monitor histories, compact row separation and reachable
Resources. No decorative emoji or icon fonts. Keep preview mode hardware-free.
Fix row heights and monitor viewport bounds, reserve both scrollbars and retain
content widths through streaming; Follow must preserve manual scrollback.
Light is the launch default; switch the complete palette without reloading fonts
or losing logs/selections. Status and USB Port own separate fixed-height frames.
Theme labels and SVGs describe the active mode; tooltips describe the switch.
Give each color one role: yellow primary/selected, coral stop/error, surface
for everything else. Cards, fields and menus share one surface and outline;
SVG icons are white strokes tinted with the button's ink.
Use exactly five logo click releases plus an 800 ms pause for Developer Access.
Reuse the main portal and security service in a separate owned helper, with
Lite-only cache/vault namespaces. Keep one portal per worker and never terminate
a portal that vetoes closing. Fixtures inject services, vault and network mocks;
tools/verify_developer.py constructs and renders the actual shared login UI.
Give monitor output the remaining height; avoid slogans and unused footer space.
Keep serial send in Connection. Source-name links open only the original source
folder through a background native file-manager call; never launch it in preview.
Replace producer-owned progress rows, preserve diagnostics and operation history,
and keep table padding intact while removing generated decorative marks.

Keep recent original sketch paths (10) and exact board names (5) in Lite's
private settings using the main history helpers and a private settings lock.
Search multiple fields through a revision-keyed index; rank exact IDs/names
first, bound results and label closest matches. Reject stale query responses.

Dispatch builds only after catalog completion and exact command acknowledgement.
Automatically resolve the selected platform's upload-target requirements even for
initial compilation, including optional uploader packages. Reuse compatible main
packages with independent native copies and byte verification; the source store
and its metadata stay read only. Publish only complete copies, stage outside
installed package directories, and download only unresolved requirements. Hold
target/action ownership through preparation and hand off once; Stop and failures
must prevent an upload, never cause retries of a device operation.
Source capture precedes Compile/Upload; Clean calls the existing backend only
against private state. The worker retains flash-write guards and passive serial
connection policy. Do not weaken target/source/output certification.
Compile needs a sketch and valid board/framework; Upload also requires a selected
connected port. Gate the Rust controls and recheck in Python before preparation
and handoff. Enable certified Skip Compile for every Upload automatically,
including after Clean clears its flag. Reuse only the main backend's verified
exact-board/framework workspace; source changes or invalid firmware force a build.

Run the scoped verifier with a private interpreter and without display variables,
including tools/verify_preparation.py for missing-uploader, reuse and cancellation
regressions, and tools/verify_history_search.py for history/search/readiness.
Run cargo test for streaming monitor geometry and readiness/query regressions.
Use the real offline uploader recipe with serial opens refused;
mock the final upload callback rather than touching a connected board.
plus locked Rust checks, strict Clippy and formatting. Real compiler qualification
is opt-in through tools/qualify_compile.py in an owned fixture with mocked ports;
qualify two actual board builds and intercept only the final device boundary for
saved-build, source-change, corruption and Clean decisions.
Retain exact evidence and unresolved native Windows/Ubuntu/USB gates. Run all
necessary build/render checks before retiring large generated scratch folders.
